# AI, confidence and evaluation
Each hazard has a distinct model allocation and feature/target policy. `ai/config/hazards.json` records readiness; no active model, trained metrics or real probability is supplied. Simulator risk scores are clearly illustrative rule-based values, not ML predictions.

`resqgrid_ai.training` consumes supplied CSV data; sorts timestamps, creates chronological train/calibration/test splits with a forecast-horizon gap, fits preprocessing only on train, calibrates only on the calibration split and evaluates untouched test data. Reports precision, recall, F1, ROC-AUC, PR-AUC, Brier score, calibration curve and false positive/negative rates. Artifacts include feature schema, target/horizon, checksum, model version and evaluation. Deployment approval defaults to false. Trusted joblib artifacts require manual provenance/approval; never load arbitrary uploaded pickle files.

Before training: approve source licenses, target labels/horizon, sensor units/window alignment, leakage checks, missingness limits, geography/time holdout, sample sufficiency and threshold cost. Evaluate under imbalanced events, drought seasonality, rare extremes, sensor drift and unseen zones. Chronological holdout is implemented; independent geography holdout and external validation remain pending. No synthetic test accuracy may be advertised as disaster-prediction performance.

Inference requires a deployment-approved, checksum-matching manifest and complete features. Missing/stale evidence produces UNKNOWN, not SAFE. The worker currently activates one artifact through `RESQGRID_MODEL_MANIFEST`; a hazard-aware multi-artifact registry/activation interface remains necessary for all four live hazards. A validated `input_quality_coverage_v1` policy produces an input reliability index, not correctness probability or a statistical confidence interval. It cannot substitute for model uncertainty research. Supporting source count currently uses distinct registered devices; independent/spatial corroboration and external weather feeds require further validation. Prototype weights .5/.25/.25, confidence .8, three persistent observations and two sources need authority-reviewed validation before `validated=true`.

Advanced work: temporal/ensemble models, satellite segmentation/change detection, explainability with validated feature attribution, drift monitoring, multimodal fusion and event-specific recommendations. Future research: digital twins, causal impact and autonomous planning. Their absence must not block establishing one genuinely evaluated MVP hazard pipeline.
