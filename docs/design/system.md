# V3 design system

The approved image landing stays unchanged. The operational workspace design uses midnight navy navigation, pearl/steel canvases with white Citizen, Rescue Operations and Administration panels, and graphite/navy Intelligence surfaces. Cobalt indicates actions in light workspaces; pale blue indicates actions in Intelligence. Teal indicates healthy/confirmed states, amber indicates caution, red indicates danger/SOS and neutral slate indicates unknown data. Colour always accompanies a text label. Maps use the same semantic sequence as the risk scale.

Typography uses Inter with an Arial/system fallback, a 16px root, 14px body/table/action text, 12–13px supporting text, 10px section labels and 28–32px page titles. Numeric operational values use tabular figures. Spacing follows 4/8/12/16/24/32/48px intervals. Panels have 12px radii, controls 8px and dialogs 14px. Borders and restrained shadows create hierarchy without glass, decorative gradients, glow or entrance animation. The only workspace gradient is a segmented, semantic risk scale; charts use subtle data fills.

Desktop staff layout: contextual left navigation, concise command header, strong page title, actionable queue/evidence panels and a large map. Citizen pages prioritize warnings and help above exploration. Mobile reduces columns and keeps navigation and primary controls readable. Buttons use text+icon, visible focus and a minimum 44px height. Inputs have persistent labels, explicit validation and review steps. Tables expose relevant state and actions inside horizontally scrollable containers. Maps pair zones with a selectable equivalent list and describe illustrative overlays; basemap failure does not hide textual evidence. Charts include units/context and inherit the workspace palette. Probabilities never imply certainty. Loading, empty, insufficient-data and unavailable integrations are explicit.

Accessibility targets: WCAG 2.2 AA, keyboard operation, native dialog focus behavior, reduced motion, visible focus, sufficient contrast, non-colour state cues and reachable controls. This is a target requiring browser/manual verification, not a completed accessibility audit. `frontend/src/design/workspaces.css` is authoritative for workspace colours and component refinements, layered after preserved base layout styles and `v3.css`. `tokens.json` records the current palette. The landing image and its accessible controls remain scoped separately in `v3.css`. See `v3-final-touch.md` for implementation and browser QA evidence.
