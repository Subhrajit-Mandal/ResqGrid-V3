# Evidence and integration contracts
Generated domain JSON schemas and `openapi.json` correspond to the current FastAPI implementation. Times are timezone-aware UTC. Device registry `sensor_channels` is an array of `{sensor_id,kind,unit}`; identity, topic, zone and registered `source_mode` must match the envelope. Registry commissioning, not a payload claim, establishes hardware provenance.

Telemetry units: temperature C; humidity %; rainfall mm over positive `window_seconds`; water level m with separately approved reference datum; soil moisture calibrated %; smoke calibrated ppm; wind m/s and deg. Broad validator ranges are physical plausibility checks, not calibrated risk thresholds. Message identity remains unchanged during retry.

Health reports connectivity, uptime, firmware, calibration, errors and optional measured battery. Prediction states its hazard, target, horizon, feature schema/snapshot, source IDs, model version, probability and separately named confidence. Risk records gates/reasons, rule version, recommendation and decision; warning publication requires matching fresh evidence. SOS captures location provenance/accuracy/time, category, people, landmark, optional description and idempotent submission. Assignment is a versioned command, not a client-authoritative agency grant. Shelter capacity is unknown unless supplied; simulated directory values are labeled.

External weather, historical GIS/imagery, SMS/email/push and private file storage integrations are not connected. API routes may evolve around validated use cases; no placeholder integration is presented as a functioning provider. Realtime contract: first client message `{token}`, server `snapshot` of authorized incidents/public or privileged warnings plus mode. Reconnect must discard cached authorization, reauthenticate and replace stale snapshots before dispatch decisions.
