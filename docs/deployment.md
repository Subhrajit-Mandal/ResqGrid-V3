# Deployment and operations
The private review site publishes the static browser simulation only. Live target remains Netlify (`netlify.toml`) + Render API/worker (`render.yaml`, `deploy/Dockerfile`) + Supabase/PostGIS + MongoDB Atlas + authenticated TLS MQTT.

1. Create fresh V3 infrastructure; do not apply migrations to V1/V2. Run `001`, `002`, `003`, `004` as migration owner. Create distinct login roles with secret passwords, inheriting `resqgrid_api` or `resqgrid_worker`; grant neither ownership nor bypass-RLS. Provision users through Supabase Auth, then explicit roles/memberships via a controlled admin process. Deploy verified zones/agencies/resources/devices and approve retention. Schema has no production seeds.
2. Configure Mongo indexes with `database.mongo.indexes.configure`, TLS/IP restrictions and separate least-privilege identities. Review retention before TTL. Configure broker per-device credentials/topic ACLs and a subscriber identity.
3. Create Render secret groups referenced in YAML with `RESQGRID_MODE=production`, appropriate PostgreSQL URLs, Mongo URI, Supabase URL, MQTT values, allowed exact frontend Origin, and optional approved artifact path. The worker and API must not share a privileged database account. Attach approved artifacts as controlled deployment inputs; none are committed. Start API and worker; verify dependency readiness separately from process health.
4. Configure frontend public Supabase/API settings only after implementing and testing live session/API/realtime adapters. Current UI deliberately remains a browser-local simulation even when VITE variables are set. Netlify redirect enables deep links.
5. CI is configured to run unit/API/build and browser tests. The final frontend pass uses local Chromium against the production bundle (isolated file responses when managed preview networking is unavailable), covering role workflows, rendering and responsive behavior. Run browser tests against connected staging in CI as well; external basemap tiles and live services were not verified here. Test private/nonpublic test deployments with synthetic data before operational activation.
6. Establish structured redacted logs, metrics/traces, broker/worker backlog alerts, failed-job review, delivery dead letters/receipts, dependency readiness, backups/restore, deployment rollback, model rollback and incident-response runbooks. These are not configured by the current templates.

No cloud databases, live broker, SMS/push provider, real account flow or production backend were deployed in this stage. Network/provider credentials and physical hardware are required for those acceptance gates.
